# Forest: 从作者图 6 恢复单个示例环境

本目录恢复的是论文图 6 左图的**一个公开示例**，不是作者未公开的 10 个随机环境或完整 400 题。所有数值来自本地作者原始矢量 PDF 的实际提取与几何检查；没有运行 GPU、路线图或轨迹优化，也没有覆盖旧实验结果。

## 来源及证据层级

- 正式论文：[arXiv:2504.10783v1](https://arxiv.org/abs/2504.10783v1)，VII-A-1：边长 10 的方形域，中心边长 7 的方形区域内 15 个圆形障碍，半径 0.35，从左下到右上。正文没有给出坐标原点、随机数发生器、seed 或具体端点。
- [作者 TeX 归档](https://arxiv.org/src/2504.10783v1) SHA-256：`18c4140e37eb05abe636dd4999612618f565c120ce57fbe966e39545b68f1986`。
- `sections/experiments.tex` 明确使用 `figures/franka_benchmark_gradient.pdf` 作为图 6。本目录 `author_figure6.pdf` 是该成员的原字节，不是页面截图。
- 原图左侧的 15 个圆、画框、端点和轨迹均为矢量路径；右侧 Franka 图是位图。`author_figure6.svg` 由系统 Poppler 转换，`vector_extraction.json` 保存选中对象的完整路径及变换、归一化前后坐标。
- 统一把画框仿射映射到 `[-5,5]^2`、y 向上。坐标原点是明确声明的约定。圆半径采用正式正文的 **0.35 m**，不从图像取近似半径。

## 实际几何验收

`geometry_audit.json` 中 9 项检查全部通过：15 圆均在正文要求的中心区域，半径吻合，显示轨迹在域内，解析线段—圆距离与独立密集采样一致，直连起终点存在碰撞，星形中心与轨迹终点一致。

- 提取轨迹 **90 个显示顶点**、89 段，长度 **10.804082096078 m**。
- 全部显示线段对全部圆的解析最小净距 **0.002667910600 m**；这只证明提取折线的几何可行性。
- 起终点最小净距分别 **1.561871055028 m**、**1.534720224077 m**。
- 直线连接的最小净距为 **−0.244252846651 m**，确实需要绕障。
- 独立检查 89,089 个采样点；采样最小值高于解析下界最多 **1.26948e-8 m**。

90 个顶点是用于画图的采样折线，**不是 DRM 原节点、样条控制点、轨迹时间或论文平均 3.45 段的证据**。没有把该曲线冒充新规划结果。

## 对原随机 seed 的有限检查

执行了 40,000 个预先声明的几何匹配：NumPy `default_rng` / `RandomState`，seeds 0–9999，`(15,2)` 或 `(2,15).T` 两种抽样排列，均匀分布在 `[-3.5,3.5]^2`，以 Hungarian 匹配比较无序圆心集合。没有调用规划器或用论文成功率筛选。

`seed_search.json` 显示：**未找到匹配**。最接近候选的圆心 RMSE 仍为 **0.777431 m**，最大匹配误差 **1.227612 m**，远大于事先设定的 0.001 m 匹配阈值。不能把该 seed 当作原 seed；也不能由有限搜索断言图不是随机生成。其他发生器、seed、拒绝采样或作者手工修改仍未知。图示应继续作为固定单场景，不能复制为十个“原论文环境”。

## 重现命令与运行记录

在仓库根目录执行，复用现有 Conda 启动器：

```bash
bash local/python.sh -m reproduction.environment_reconstruction.forest_reference
```

命令会核验作者源归档 SHA，提取指定成员，实际执行 `/usr/bin/pdftocairo -svg` 与 `/usr/bin/pdftoppm`，重新提取和验证，执行上述有限 seed 搜索并保存图及证据。内部命令 stdout、stderr 与退出码保存在 `execution.json`；几何审计输出保存在 `extraction_run.log`；稳定产物和源文件 SHA 见 `source_manifest.json`。

首次工具探测中的默认 `pdfinfo` / `pdftoppm` 命中了 Codex bundled Poppler，因 Ubuntu 22.04 缺少其要求的 `GLIBC_2.38` 而失败。失败保存在 `initial_tool_failure.json`；随后显式使用现有 `/usr/bin/` Poppler 成功，无安装或替换 Conda 依赖。最终原图及重建图均实际渲染并目视核对。

## 对后续运行的用途

该环境可作为一个拥有原图障碍位置与端点的规划回归案例。规划器运行应重新生成路线，不能把 `reference_path` 当作算法输出。原图、旧 v5 题单和按正文构造的新随机分布应保留各自标识；此处没有把新的图示端点回写到旧 v5 配置。
