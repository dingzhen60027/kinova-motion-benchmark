## 实现与配对

新驱动只登记 `NTO_PAPER` 两个目标，直接进入原始 `paper_nto`，没有传入配点细化选项。`NTO_REFINED` 仍经独立分支调用、使用独立名称。原始版本保留零安全裕度、149 个内部配点和单次求解；强化版本不被替换成原论文标签。

本次直接逐项读取八份 run manifest，确认 **380 个新增任务 + 950 个复用任务 = 1,330 个方法观测**。它们严格对应 190 个固定任务/路网组合，各有七个方法/目标组合。每个 job 的完整 case、method seed、solver seed 都与原 manifest 一致。solver seed 在原记录中明确标为未使用，当前求解器由固定 DRM 初值确定性启动。

新旧 execution freeze 的下列映射逐项完全相等：运行源码 37 项、求值配置 21 项、路网文件 15 项、外部依赖文件 1,780 项、输入文件 97 项。因此现有复用满足真实的相同环境与实现条件，而非仅检查 Git commit 相近。

## 时间、失败与统计

共同外部计时在 worker 进程创建前开始，60 秒 watchdog 包含导入、模型和路网加载、GPU 初始化、规划、验证及输出。内部求解器取得剩余预算，不另起 60 秒。超时进程终止开销可能令记录的冷启动墙钟略高于 60 秒；这部分仍属于超时，不能变为成功。

`warm_query_seconds` 是同一次冷执行中扣除设置阶段后的实际在线分段时间，不是重新执行一次热启动规划。DRM 对照使用预先指定 LSCS 调用的前端数据，不从多次方法调用中择最快值。

输入选择为全部 smoke/dev 登记项，保留无效端点和前端失败。resume 不重跑已封存的成功或失败；只有未封存的协调程序中断会保留旧记录并建立新尝试，不按是否成功择优。场景聚类重采样保留同一场景的多个端点和路网重复，成本比较限制于同目标的共同成功任务。
