# Formal result renderer

This is reporting preparation. It does not indicate that the formal runs or
their audits have finished. No formal score table is generated by the interface
tests described below.

`render_formal_report.py` writes
`reports/benchmark_v1_formal_baselines.md` and six static PNG figures only after
the required complete evidence passes its gates. It does not alter the dev
report, runtime, frozen inputs or solver configuration. Do not run the metrics
exporter, complete audit or renderer concurrently with timed formal planning.

## Required evidence

1. Main metrics from all 15 main blocks, including invalid-input accounting.
2. Scaling metrics from all 24 source blocks, filtered by the frozen 80-ID list
   **after** their integrity verification. They contain all four requested node
   budgets. The 6000-node observations must equal the selected main observations
   field for field; they are reused, never counted as new runs.
3. The frozen approved protocol and prepared run index.
4. An audit bundle created after input, integrity and independent audits pass.
   The bundle binds the exact metrics files to the audited runs. A successful
   planner return or a `complete` flag in metrics alone is insufficient.

All 420 registrations stay in main accounting: 395 valid input problems and 25
input generation failures. The size subset has 80 registrations, 75 valid. The
two metrics views overlap: 6300 main + 4800 scaling − 1200 reused = 9900 distinct
registered slots, including 9300 legal planning calls and 600 invalid slots.
These are the frozen design counts, not success counts.

## Rendering command

After the independent audit driver has produced a passing
`formal_audit/integrity_audit.json` and both metrics exports exist, bind them:

```bash
bash local/python.sh -m benchmarks.generic_motion_v1.reports.baseline_study.audit_formal_study seal-bundle \
  --integrity benchmarks/generic_motion_v1/reports/baseline_study/formal_audit/integrity_audit.json \
  --main-metrics benchmarks/generic_motion_v1/reports/baseline_study/formal_main_metrics/metrics.json \
  --scaling-metrics benchmarks/generic_motion_v1/reports/baseline_study/formal_size_metrics/metrics.json \
  --output benchmarks/generic_motion_v1/reports/baseline_study/formal_audit/audit_bundle.json
```

Then render, substituting the actual metrics and sealed bundle paths:

```bash
bash local/python.sh -m benchmarks.generic_motion_v1.reports.baseline_study.render_formal_report \
  --main-metrics benchmarks/generic_motion_v1/reports/baseline_study/formal_main_metrics/metrics.json \
  --scaling-metrics benchmarks/generic_motion_v1/reports/baseline_study/formal_size_metrics/metrics.json \
  --audit-bundle benchmarks/generic_motion_v1/reports/baseline_study/formal_audit/audit_bundle.json
```

Optional `--protocol`, `--run-index` and `--output` arguments select explicitly
named evidence or output files; `--no-figures` suppresses PNG rendering.
There is no option to bypass failed or absent audit evidence. The default
protocol and index are `formal_protocol_v1.json` and `formal_run_index.json` in
this directory. Calling the script without completed evidence fails without
writing a formal report.

The renderer consumes the two metrics JSON files and small audit/metadata files;
it does not call a planner, GPU, solver, collision checker, full receipt verifier
or bootstrap. It checks the fixed matrix, five-method pairing, all legal latency
values, success gates, observed counts, stored scalar statistics, eligible stage
counts and 6000-node reuse. Statistical intervals come from the frozen metrics/scene-cluster bootstrap
implementation and its statistical regression tests. The independent auditors
verify receipts and trajectory evidence; they do not independently recompute
bootstrap intervals.

## Audit bundle contract

The independent audit driver creates the bundle after metrics export. The
following describes field names, not an acceptable substitute for an audit:

- `schema_version: 1`, `kind: "formal_baseline_audit_bundle"`.
- `complete: true`, `passed: true`, `errors: []` only following actual success.
- `protocol_sha256`, `source_code_commit`, `run_index_sha256`.
- `metrics_sha256`: `main` and `scaling` file hashes.
- `run_manifest_sha256`: every absolute run directory mapped to its frozen
  manifest hash, exactly matching the 24-block index.
- `evidence.input`, `evidence.integrity`, `evidence.independent`: each contains
  a `path` and `sha256`. Relative paths resolve from the bundle directory.

The input evidence is the approved `test_full_reaudit.json`, including the test
manifest hash and input accounting. Integrity and independent evidence may refer
to the same combined audit JSON. That audit must contain `complete`, `passed`,
`integrity_passed`, `independent_passed`, `all_outcomes_reviewed`, an empty
`errors`, the protocol hash, the full `run_manifest_sha256` mapping,
`covered_job_slots`, and all five labels in `reviewed_methods`. The independently
audited source reports and raw failed outcomes must remain available behind that
summary; hand-authoring passing flags does not constitute verification.

## Report interpretation

- Minimum distance and minimum time are separate. `obstacle_main` and
  `open_control` are separate tables and figures.
- Main success divides by all legal queries, retaining unsupported solvers,
  frontend failures, optimizer failures, collision failures, timeouts and
  infrastructure errors. Native-DRM and strict-seed conditionals are auxiliary.
- All-legal cold latency includes failed outcomes. Validated-output latency
  leaves unsuccessful mass at infinity; termination latency includes quick
  failures. These are observed fixed-60-second-run curves, not shorter-budget
  experiments or first-feasible-iterate time.
- Successful costs describe selected successful subsets. Paired cost and time
  differences use common-success tasks; all-legal paired time retains failures.
- Backend-stage means require complete return of candidate and final validation.
  Normal returned solver failures remain eligible. Every backend stage of an
  incomplete call is excluded, even if early work completed; raw timing stays
  saved. Missing values are never filled with zero.
- Scene bootstrap keeps endpoint and roadmap repeats together. A single control
  world has no scene-generalization CI. Degenerate 0%/100% bootstrap intervals
  do not prove population probability is exactly 0/1.
- Four-size comparisons keep the same fixed IDs. Successful-cost curves are
  descriptive, since the successful subsets can differ across sizes. Requested
  and retained nodes are displayed separately; offline time is separate from
  online query time.
- Numerical trajectory validation is not a continuous collision-freedom proof.

## Small interface tests

These tests use five synthetic in-memory rows and tiny protocol dictionaries.
They do not read actual formal run directories and are not experimental data.

```bash
bash local/python.sh -m unittest \
  benchmarks.generic_motion_v1.reports.baseline_study.test_formal_renderer -v
```

They cover incomplete/incomparable evidence, absent methods, duplicate reuse,
unsealed attempts, missing failed-query latency, missing success gates, changed
fixed inputs/runtime, old stage schemas, wrong block attribution and missing
integrity verification. The fixed matrix test retains an invalid input slot;
it never selects cases by planning success.
