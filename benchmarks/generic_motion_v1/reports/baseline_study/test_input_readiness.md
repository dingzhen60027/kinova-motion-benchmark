## 3. 25 个无效输入的原因

无效题全部集中在以下 5 个布局，每布局 5 题，**25 题的 q_start 与 q_goal 都是 null**。每题恰好用完 4096 个原始候选，全部在碰撞/最小间隙规则处被拒绝，距离分层拒绝均为 0。合计 102,400 个候选不是长距离目标难采，也不是某个规划算法失败导致删题；它们在建立有效起点之前就已耗尽预算。

下表所有构型数来自新增固定的 128 个 CPU 诊断候选，不外推为全 C-space 结论：

| 无效布局 | 无新增障碍时合法构型 | 原始物理障碍下完整合法构型 | 冻结球覆盖下完整合法构型 | 判断范围 |
|---|---:|---:|---:|---|
| test-sparse_clutter-017 | 79 / 128 | 0 / 128 | 0 / 128 | 原始障碍已在全部诊断状态与肩部碰撞 |
| test-dense_clutter-002 | 80 / 128 | 0 / 128 | 0 / 128 | 原始障碍已在全部诊断状态与肩部碰撞 |
| test-dense_clutter-009 | 83 / 128 | **8 / 128** | 0 / 128 | 有原始几何合法状态被保守覆盖拒绝 |
| test-dense_clutter-013 | 80 / 128 | 0 / 128 | 0 / 128 | 原始障碍已在全部诊断状态与肩部碰撞 |
| test-route_choice-011 | 75 / 128 | **46 / 128** | 0 / 128 | 有原始几何合法状态被保守覆盖拒绝 |

所有 5 个布局的覆盖球与固定基座/设备都没有穿透；最小距离分别约为 73.29、41.64、21.36、42.53、108.09 mm。新增障碍主要挡住的是**可动肩部和上臂**。所以不能将其归因于“固定基座被场景穿透”，也不能简单说整片工作空间被障碍填满。

`dense_clutter-009` 和 `route_choice-011` 合计 54 个 CPU 状态构成明确的反例：原始物理几何下满足 0.1 mm 间隙，但统一保守覆盖使其不可接受。其他 3 个布局的 128 个状态均物理碰撞，只能支持“诊断样本持续受阻”，不能支持全局不可行证明。102,400 个冻结候选全失败，也不能证明继续采样永远不会找到合法构型。

## 4. 保守覆盖与数据代表性的边界

球半径仍固定 0.04 m；源几何相交的网格单元由包围球覆盖，float32 球心与冻结数组完全一致。本次所有非空场景的最小单元覆盖余量为 **5.396 mm**，没有发现漏覆盖、坐标错位或哈希不一致。

但**保守覆盖正确不等于原始物理自由空间保真**。记录中的单个覆盖球相对于源几何的外扩上界最大约为 **74.60 mm**，这是保守上界而不是每点实际外扩量；上表的 54 个构型已实测展示了这种表示的实际代价。所有方法共享同一覆盖，因此 v1 内方法比较仍使用相同合法域；如果论文将其直接描述成原始小球/薄墙的规划性能，就会过度解读结果。

另外，bottleneck/route_choice 的中心采样范围仍固定于生成源码，ROI JSON 并不直接控制这两个族的全部位置分布。源码已冻结，所以可复现；“所有族全部由 JSON 配置”目前不成立。

## 5. 重复、近重复和跨 split 泄漏

80 个非 open 测试布局有 80 个不同几何散列。test 与 smoke/dev 没有非 open 几何、scene seed、endpoint seed 的精确交集；此前全量审计也确认单端点及端点对无跨 split 重复。每个布局内 5 题共享场景是规定设计，3 套 DRM seed 在所有场景复用也是配对设计，均不能当作额外独立环境。

本次还做了不用于筛题的近重复诊断：

- 非 open 冻结球心集合的对称 Hausdorff 距离：test 内最近布局对为 126.78 mm；test 与 smoke/dev 最近为 67.79 mm。以明确声明的 10 mm 诊断阈值检查，近重复对为 0。
- 全部合法 test 单端点对 smoke/dev 单端点的最小关节范围归一化 RMS 距离为 0.063974；以 0.01 诊断阈值检查，近重复对为 0。

这些几何距离没有证明场景在所有意义上独立，也没有证明 C-space 拓扑不同。它们补充排查了复制场景、轻微改动副本和端点重复；没有根据这些后验距离重选测试题。

## 6. 正式测试前的决定

1. **若保留 v1：** 冻结现有 420 条登记记录，明确只有 395 个合法规划题，25 个为预先确定的输入生成失败；固定上述有效分母、每族数目和聚类单位后再运行算法。不要换端点、半径或场景，不把无效输入转成算法失败。
2. **若要求完整的 420 个有效且均衡的题：** 建立新版本、保存 v1 和全部拒绝记录。新方案可在 dev 上预先确定合法端点接纳规则、有限候选预算与场景重采样规则，并检查肩部附近静态遮挡；只根据输入合法性规则接受场景，绝不能用 EI-ZO/NTO/任何规划器成功筛选。
3. **若希望更贴近原始物理几何：** 在新版本中量化覆盖外扩及原始几何与覆盖模型的合法构型差异，并在全部方法中冻结统一表示。调整覆盖分辨率、半径或位置分布都会改变协议，不应就地修补 v1。

### 可选 v1.1：只替换 5 个无效布局的最小方案（未实施）

如果选择在正式算法测试前补齐 420 个合法端点问题，以下是较小、可审计的协议修订。它是建议，没有执行，没有修改本次输入：

1. 预先固定替换集合为 `sparse_clutter-017`、`dense_clutter-002/009/013`、`route_choice-011`，每个布局 5 题。395 个原合法题的障碍、球覆盖、端点、距离层及原始 NPZ 均原样继承，保留逐题原 SHA；v1 全部记录继续冻结。
2. 机器人、碰撞过滤对、0.04 m 球半径、原始几何分布、ROI、关节裕度、最小间隙、4096 端点候选预算、5 题距离层序列均不变。新增版本只引入明确的“布局内全部 5 对端点合法”接纳条件。
3. 用 `v1.1 + 原 scene ID + candidate attempt` 派生独立场景和各题端点 seed。按确定顺序生成候选，接纳**第一个**全部 5 题通过输入合法性检查的布局；不按直连阻塞比例、路径长度、规划器成功、时间或排名选择候选。
4. 预先规定有限的替换候选布局上限，例如每个原 slot 最多 32 个。所有候选继续使用当前固定设备几何拒绝规则，并保存每个候选的原始几何、体素、5 题全部候选和拒绝原因；不能只保留最后接纳的题。到达上限仍未补齐时发布 `incomplete` 记录，不放宽半径、间隙或端点约束。
5. 新 manifest 和配置使用显式版本、新协议散列和逐题 lineage，关联 v1 原 scene/problem SHA。对继承的 395 题做字节/数值不变校验，对 25 个新题做完整输入审计，检查跨 split 精确重复，再冻结新版本。当前审计器有严格 v1 版本约束，不能只手工改 JSON 版本字符串绕过；需让代码显式支持新协议及其历史来源。
6. 最终题单可以是四个主族各 100 个有效题加 20 个 control，但应另报生成拒绝率。这个题单是 v1 的修订版，**不是另一套独立的 420 题数据**；75 个原有随机布局和全部 control 被沿用。

这种 v1.1 合法性重采样不需要任何规划器，也没有选择“算法容易成功”的题。不过它把环境分布条件化为能采出指定端点的布局；它只能修复题单缺少有效输入，不能消除保守覆盖对原始物理自由空间的改变。若需要改变覆盖分辨率或半径，应进一步使用清晰的新几何协议版本。

此次 CPU 重验结合已验证的完整 GPU 输入审计，没有发现现有 395 个合法题存在需要修正的端点/文件错误，因此没有必须立即重跑 GPU 的依据。如需另存一份新的完整 GPU 审计，可在当前建图任务完成后执行以下**仅输入检查**命令，不运行规划器：
