## 3. 应冻结的指标定义

| 指标层 | 冻结口径 | 解读限制 |
| --- | --- | --- |
| 完整成功 | 最终封存状态 `success_validated_numerical`，求解器成功、端点/限位/运动约束及统一双 checker 验收均通过，外层无超时 | 保存过可行候选但最终求解失败或被杀进程，仍是失败 |
| 失败类别 | frontend_failed、solver_failed、collision_failed、limit_failed、validation_undetermined、timeout、unsupported、infrastructure_error，另列 invalid_endpoint | 未完成任务是 pending，不是失败实验；完整论文表要求零 pending |
| 公共前端 | 原生 DRM 返回率、严格 seed 准入率、成功/原生 DRM、成功/严格 seed，全部并列 | 目前 dev 的原生分母 111 与准入分母 110 不同；前端失败不证明任务无解 |
| 距离成本 | 固定端点间 PWL 欧氏长度，单位 rad；另报既有归一化关节长度 | 不与时间目标混排；不能因 NTO 成功子集较易就以其边际均值宣布更优 |
| 时间成本 | 连续曲线持续时间 T，单位 s；统一各轴 1 rad/s、1 rad/s²、端点零速度 | 轨迹持续时间与规划计算时间是两个量；PWL 不提供合格的最短时间基线 |
| 延迟 | 合法任务的冷端到端墙钟 p50/p90/p95、均值及最大值；成功/失败分别报告 | 失败快速退出可缩短平均值，因此耗时不能脱离成功率单独排名 |
| 成功截止曲线 | `F(t)=合法任务中最终严格成功且冷完成时间<=t的数量/合法任务数`；预先固定 t=1/5/10/30/60 s | 失败、unsupported 和超时在全部 t 上均贡献 0；这是 60 s 协议的完成曲线，不是改时限后重跑结果 |
| 组件耗时 | 初始化、collision-map/query、DRM、inflation、optimization、recovery、validation 分开；每格附实际观测 n | 未执行/异常中断为 null，不能填零；部分失败没有返回阶段时间 |
| 资源与机制 | 离线路网构建时间/节点/文件大小；在线显存采样峰值、区域数、面数、修复次数 | 0.2 s 轮询的显存不是精确分配器峰值；区域数不能等同碰撞查询量 |
| 数值质量 | 最大端点/限位/速度/加速度残差、最小采样距离、采样点数、checker 分歧及接触未决数 | 有限采样不是连续证明；EI-ZO API 未暴露统计接受状态，不声称每个区域获得 δ/ε 证书 |

成功截止曲线以外，保留真实超时清理墙钟；超时清理使观测值略大于 60 s，不把日志裁短。若构造截断时间统计，必须另列其定义，不覆盖原始 wall time。warm 当前是同一次冷执行扣除初始化的阶段时间，不能命名为独立热启动重复实验。若研究需要常驻进程热启动性能，应在另一个协议中实际执行并记录预热，不从冷时间推定。

**成对比较**固定键为 `(problem_id, roadmap_id, method_seed, objective)`。核对输入、初始 DRM 路径及前端准入的一致性后，报告：全部合法配对的成功率差；双方都成功的成本差；全部合法已完成配对的冷耗时差；另给双方都成功的冷耗时差。成本和共同成功耗时同时标出共同成功 n 与场景数。主要距离对照为 LSCS–LGCS、LSCS–NTO-distance，时间对照为 SCSTO–NTO-time；LGCS–NTO-distance 为次要对照。全部使用同一场景聚类，禁止对各自成功样本均值相除得到“加速倍数”。报告描述性 CI，不把未经多重比较控制的区间包装成全体比较的显著性结论。

## 4. 现有汇总中需补足的报告逻辑

`summarize.py` 已正确实现合法任务成功分母、open_control 聚类、封存检查、配对键唯一性、共同成功成本、失败耗时、缺失不填零及离线路网单列。这些实现应复用。以下是本轮正式统计前应补齐的分析输出，**不需要改变规划算法**：

- `_group()` 的 `all_finished`、`success`、`failure` 耗时分组未先过滤合法输入。dev 全部合法故现有 dev 表不受影响；test 中 25 个 invalid 题快速退出会拉低“全量”延迟。正式主延迟表必须基于 `input_legal=True`，全请求耗时另列，不能直接照搬 `all_finished` 标签。
- 现有 `_paired()` 成本为共同成功条件量，但时间为双方已完成的合法任务条件量。两者正确且回答不同问题；增加共同成功的冷耗时与截止成功曲线，不能把当前冷耗时差解读为“成功求解加速”。
- 显示完成中间状态的汇总可包含 pending；正式报告必须要求完整计划、所有 receipt 封存、输入和源码 hash 一致、重复键为零、失败不删。续跑是执行中断恢复，不能把算法失败反复尝试到成功。确需新版本重试时另建协议，旧失败保留，不能只挑最新成功 attempt 改写主表。
- 现有统计缺少明确的主族宏平均、输入困难分层、合法任务截止曲线和共同成功时延；可以对封存 dev 只读派生。实际组件时间没有记录的部分不能通过相减猜造。原论文“TO+CS”与当前含验证/IO 的阶段边界不同，继续保留边界说明，不宣称论文速度倍数复现。
- `solver_seed` 已保存但当前 manifest 声明 `solver_seed_used=False`，求解器由固定 DRM 路径确定初始化。应按实际记录说明，不称每题具有额外独立 solver 随机重复。

路网规模 80 题建议覆盖四主族各 20 个原始 scene_id，每场景选 1 对端点，open_control 保留在主评测中。选择必须在任何 test 求解前固定 ID 文件和 SHA；不查看规划结果。可采用以下完全确定的规则：每族按 `SHA256("generic-motion-v1-size80:scene:" + scene_id)` 排序，前 8 个场景取 short、接着 8 个取 medium、最后 4 个取 long；场景内按 `SHA256("generic-motion-v1-size80:case:" + problem_id)` 取对应档的第一题。这样保留输入设计的 40%/40%/20% 距离档比例，并覆盖全部 80 个主族场景。无效场景也照选，不能跳过；本输入下将是 75 合法、5 无效题。本文未生成该 80-ID 文件，执行者仍需保存实际选择及校验。

四个规模复用相同三个 DRM seed、构建参数和算法种子配对关系；每份地图按自身实际节点数、模型/配置/产物 SHA 标识。应另外构建 3 个规模 × 3 seeds 的 9 份地图；6000 的 3 份已存地图按 SHA 复用。所有建图时间、文件体积和失败单列；旧 6000 的两次构建窗口曾有重叠，不能拿它们和新串行建图直接宣称离线规模加速。如果要严谨比较离线构建时间，单独以统一资源协议重测全部规模，不能抹去原始观测。

dev 的直连受阻题为 **47/60**，直连未检出碰撞题为 13/60；test 为 290/395 与 105/395。困难分析的首要子集就是输入已固定的 47 个 dev 受阻题，不另造有利分布。`bottleneck`、`route_choice` 仅是工作空间形状标签；现有 bottleneck 的高成功率也表明名称不能代替实测难度。seed 准入失败、NTO 失败、LGCS 许可超限等结果相关子集只能用于诊断，不能改变总体分母或作为唯一方法比较集。

实际预算重跑时保持相同模型、输入、方法表达、初始化与验证器；改变的是外层 wall deadline，原求解器配置不为某方法单独重新调优。60 s 是主结果，10/30 s 是声明的开发敏感性点，不应根据哪个点更有利再挑选。若改变了 runtime 或求解器选项，旧 60 s 不能直接当作同版本对照，应完整重跑对应开发矩阵。

规范 §8 要求等新增碰撞查询/区域预算，这对后续局部 refinement 方法的机制对照仍必要。但当前 NTO 不生成 EI-ZO 区域，原生 EI-ZO 也没有完整公开的逐查询计数；不能用区域数或 `num_particles` 假代总碰撞计算量。现阶段冻结等总时间预算和可观测资源统计，将精确查询预算明确标为未实现，不为追求表格齐全修改上游 CUDA 或新增 refinement 方法。

## 6. DRM 公平性、许可证及正式运行边界

**DRM 参照。** 路网、端点和第一条原生路径必须对各方法相同，严格 seed 准入门槛相同。LGCS 第二路径搜索、验收和膨胀是该方法自身额外工作，应计入其在线预算；第二路径找不到时的首路径回退要记录，不能将多算一条路径的耗时算给公共前端。原生 DRM 路径若未通过严格验收，只能标为无效 seed，不能作为成功 raw-path。对合法 seed 可重算长度、归一化长度、采样距离；与优化结果的长度改善仅在同题、同 seed 且最终成功时配对。raw path 没有满足时间目标的连续速度/加速度参数化，不产生时间优化成本。

从五方法保存的相同 seed 数组和阶段时间派生 DRM 诊断是合理复用，但不能把某个完整优化进程的总墙钟称为 DRM-only 的端到端时间。若需要独立“DRM-only 延迟”主表，应另行真实执行初始化→DRM→共同验证的固定入口；在此之前仅报告已观测的 DRM 阶段时间，缺失记 null。优化器间不允许用更密碰撞检查或更宽连接搜索为某一方重新选 seed。

**许可证与后端。** 现有 LGCS dev 的 16 次 `unsupported` 来自 Gurobi 规模许可；它们必须计入现有部署成功率，同时单列“不支持”而不是算法无解。正式运行前冻结实际许可证能力和求解器版本。若合法的大规模许可仍不可用，可以完整记录同一受限部署轨道，但不能据此推断 LGCS 方法可靠性更低，也不能将许可成功子集当作无偏算法排名。若许可后来改变，建新协议并重跑全部对应 LGCS 任务，不能只补成功原来超限的项。不能删区域、换碰撞球或改用 LSCS 填补许可失败。

现有五方法共同出现的 `closest_node >= 0` 原生退出发生在优化之前，应归前端基础设施错误；NTO 的 Drake `BoxBoxGradient()` 导数断言是后端异常。SNOPT infeasible/iteration limit 不证明规划全局不可行，失败求解器留下可行采样也不改成成功。正式前可在开发集修复确定的接线或后端问题，但必须保存旧证据、声明新源码版本、重跑受影响的完整开发对照并通过审计，不能在 test 出分后只为失败题修补或调参。
